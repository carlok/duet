# Lean certificates

Lean 4 proofs of results that the pipeline reports. The layout follows `curve-symmetry-lean`: compiled Mathlib is
reused from an existing Lake project, Lake is never run, and nothing is fetched at check time.

| Module | Statement | Proof |
|---|---|---|
| `Duet/S10.lean` | The theory S10 (five laws) has a 10-element model; S10 implies none of `x·x = x`, `x∘x = x`, `x·(x·x) = x`, stated over all types | `decide` on the tables |

Check (Lean 4.35.0 in the `soup-lean` image; Mathlib v4.35.0 from a compiled Lake project, mounted read-only):

    podman build -t soup-lean lean/
    podman run --rm -v "$PWD/lean:/src" -v "<Lake project with compiled Mathlib v4.35.0>:/reuse:ro" soup-lean sh /src/check.sh

`check.sh` compiles every module with `-DwarningAsError=true`, then `verification/Audit.lean` checks that every
declaration in the namespace `Duet` uses only the axioms `propext`, `Classical.choice` and `Quot.sound`. That
excludes `sorry` and `native_decide`. This is a local audit, not a Palomar dry run.

Modules are generated by `python -m soup.lean_cert` from checked results (`work/check/*_model.json`). Generated
files are committed. Regenerate a module only from a result that `soup.check_offline.check_finite` accepted.
